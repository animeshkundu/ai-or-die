Step 3 — is it xterm, or the wheel delivery?

Normal-buffer scrolling is dead on this machine but works elsewhere with identical code — so the cause is this machine's runtime. This probe runs a programmatic scroll that never touches the wheel, which splits the two possibilities cleanly.

Get to a plain shell first

  1. Leave the Claude TUI so the buffer is normal: Ctrl+C to a shell prompt (or open a plain shell tab).
  2. Make scrollback: run seq 1 300 (Git-Bash) or 1..300|%{$_} (PowerShell) so the screen overflows.
  3. Paste the probe, read the output.
  4. Then drag the scrollbar on the right edge with the mouse/trackpad — note if that scrolls.
(() => {
  const t = window.app.terminal;
  const vp = document.querySelector('#terminal .xterm-viewport');
  const a = t.buffer.active;
  console.log('=== env ===');
  console.log('UA       :', navigator.userAgent);
  console.log('platform :', navigator.platform, ' dpr:', window.devicePixelRatio);
  console.log('=== buffer ===');
  console.log('type:', a.type, ' viewportY:', a.viewportY, ' baseY:', a.baseY, ' length:', a.length, ' rows:', t.rows);
  console.log('viewport DOM:', vp && { scrollTop: vp.scrollTop, scrollHeight: vp.scrollHeight, clientHeight: vp.clientHeight, overflowY: getComputedStyle(vp).overflowY });
  console.log('=== programmatic scroll (bypasses the wheel entirely) ===');
  const y0 = a.viewportY;
  t.scrollLines(-5);
  console.log('scrollLines(-5): viewportY', y0, '->', t.buffer.active.viewportY, ' | vp.scrollTop:', vp && vp.scrollTop);
  setTimeout(() => t.scrollToBottom(), 400);
})();

What it splits

ResultMeaning
scrollLines(-5) moves viewportY (and scrollbar-drag works) xterm can scroll fine — the wheel just isn't driving it. Cause is wheel delivery on this machine: an extension, the browser, or a remote-desktop layer eating/altering wheel over the terminal.
scrollLines(-5) does not move viewportY (scrollbar-drag also dead) xterm's viewport itself can't scroll here — deeper: renderer/layout/clientHeight on this box. Different fix (likely renderer or a viewport-metrics issue).
length ≤ rows No scrollback captured at all — the PTY/session isn't retaining lines (the node-pty-over-network angle).

What the pipeline missed

Critical  The memory safety valve is built but not wired up

This is the one that most directly contradicts "runs for days without crashing", and the report does not mention it.

RestartManager._checkMemory() runs every 5 minutes. Past the GC threshold it schedules a GC; past the warn threshold it broadcasts memory_warning to clients, throttled to once every 30 minutes. That is all it does.

initiateRestart() — defined at restart-manager.js:89 └─ only caller: server.js:3862, reason = 'user_requested'

Meanwhile bin/supervisor.js:184 already handles RESTART_EXIT_CODE (75) and respawns cleanly. So the entire self-healing path exists and works — the memory monitor simply never pulls the trigger. Under sustained growth the service warns every 30 minutes, forever, until the OS or V8 kills it.

Fixing findings 1–8 slows the growth. Wiring this closes the failure mode. I'd fix both.

The measured reproduction

An isolated 8-second flood workload at 4 MiB/s failed the memory gate at 11,750 MB/h against a 2.5 MB/h threshold, ending with 29.4 MiB across four inactive sessions. V8 attributed string +30,894,800 shallow bytes on this retained path:

OutputBufferFloodWorkload → ClaudeCodeWebServer._server → claudeSessions Map → Session → outputBuffer → CircularBuffer

That rate is a deliberately saturated probe, not a production forecast. What it establishes is the retainer, and it matches findings 1 and 2 exactly. Notably external stayed at 3.9 MB and array_buffers at 0.1 MB throughout — so this is JS-heap string retention, not node-pty native memory, not a Buffer leak, and not V8 fragmentation.

Recommendation

Dispatch fast-feature-opus5 to fix, scoped to the verified list. My proposed brief:

  • Findings 1 + 2 together — one byte-accounted scrollback representation with both an item and a byte bound, splitting at safe output boundaries, with reconnect replay consuming that same bounded structure; plus shrinking raw scrollback at PTY exit instead of holding it for 7 days. These are one fix, not two.
  • The missed finding — wire _checkMemory() to initiateRestart() above a hard ceiling, reusing the existing 5-minute rate limit and the supervisor's exit-75 path.
  • Findings 3–8 — bound review chat/snapshot bytes and expire ended reviews; byte-cap pendingText with a truncation marker; drop the VS Code readiness buffer once ready; delete _controlSessionSeq with its parent; add a BaseBridge subclass exit-cleanup hook invoked unconditionally from DELETE; call UsageAnalytics.cleanup().
  • Land the recovered probe tests as the regression gate, so each fix has to move a measured number.

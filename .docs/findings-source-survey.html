Source survey: consolidated findings

Four parallel surveys plus direct checks. Every finding below I verified against the source myself — the surveys produced a significant number of false positives, listed at the bottom so you can see what was filtered out.

The pattern worth more than any single bug

Six of the confirmed defects have the identical shape: the correct implementation already exists elsewhere in this repo, and one call site doesn't use it. Not knowledge gaps — drift.

Confirmed — ranked

high1. Auth token compared non-constant-time, on an unthrottled pre-auth endpoint — server.js:1296 
const valid = token === this.auth;    // primary auth token, plain ===

// meanwhile, for the LESSER asset token:
crypto.timingSafeEqual(expected, actual);   // artifact-review.js:52, :740

/auth-verify is registered at line 1290, before the auth middleware at 1306/1319, so it is reachable unauthenticated by design. _perIpRateLimit exists at server.js:910 and is applied to git-show (30/60s) — but not here. So the endpoint is unauthenticated, unthrottled, and leaks comparison timing on the one secret that matters.

Compounding it: CLAUDE.md:142 documents "Rate limiting (100 requests/minute per IP by default)". That global limiter does not exist. Rate limiting is opt-in per route on a handful of endpoints. Anyone reading the docs believes brute-force protection is on when it is not — which is worse than knowing it is off.

Fix: timingSafeEqual over equal-length buffers, plus _perIpRateLimit on /auth-verify. Both primitives already exist. Then correct the documentation.

high (windows)2. UNC paths silently corrupted — utils/file-watcher.js:90 
return out.startsWith('\\\\?\\') ? out.slice(4) : out;              // blind slice

out = out.startsWith('\\\\?\\UNC\\') ? '\\\\' + out.slice(8) : out.slice(4);   // server.js:670

realpathSync.native returns \\?\UNC\server\share\project for a UNC path. slice(4) yields UNC\server\share\project — an absolute network path silently becomes a malformed relative one, so watcher subscription matching fails on network shares. Windows is the primary target, and the repo already documents this exact trap ten files away.

medium-high3. Unanchored PowerShell spawn — model-host-containment.js:55

execFile('powershell.exe', ...) resolves through PATH, while server.js:7049, terminal-bridge.js:115 and hibernation-guard.js:77 all anchor to SystemRoot\System32\.... With a stripped PATH the orphan model-host sweep silently never runs (so orphans accumulate unnoticed); with an attacker-ordered PATH it is an execution surface.

medium4. Artifact panel does not survive a browser refresh — your report, confirmed

Review state is broadcast as a one-shot event (artifact_review_opened, artifact-review.js:913) fired only inside POST /:sessionId/open, and never replayed. localStorage persists layout only (left, top, width, height, minimized). There is no rehydrate fetch. So a refresh yields an empty reviews Map while the server still holds the review in ArtifactReviewStore._reviews.

Fix (server-side, no client change): re-emit artifact_review_opened on join when a live non-dismissed review exists. session_joined (server.js:4159) already replays state for exactly this reason. The client handler at app.js:3338 is unchanged; it only needs idempotency. This also fixes a second case free: attaching from a phone mid-review currently shows nothing.

Different failure, worth knowing: _reviews is in-memory only, so this covers refresh and reconnect but not a server restart, which loses the review outright.

low6. Smaller confirmed items
  • session-manager.js:139 — overlapping notifications capture • title as originalTitle, leaving a permanent bullet in the tab title.
  • server.js:454 — the .crash dump is a non-atomic writeFileSync to a fixed filename, so a kill mid-write truncates it and consecutive crashes overwrite. writeFileSync to temp + renameSync fixes it without breaking the sync constraint. (The primary sessions.json write is already properly atomic.)

Verified healthy — worth knowing what not to worry about

clean
  • Path traversal: _canonicalizePathSync canonicalizes both sides with realpathSync.native, recurses to the parent for non-existent leaves, strips both \\?\ and \\?\UNC\, and compares via path.relative. Correct.
  • sessions.json durability: temp file + fsync + rename, parent-dir fsync on POSIX, and an in-flight promise-chain lock serializing concurrent saves. Restore forces active: false with cleared connections.
  • Crash-capable paths: WS frames size-capped before JSON.parse, parsing in try/catch, shapes validated, .catch() on async handlers, PTY listeners disposed, spawn rollback, 30s watchdog, Windows Job Objects for process-tree reaping.
  • Secret redaction (PEM, bearer, AWS/GitHub/OpenAI keys) before text reaches the summarizer. Dependencies: zero vulnerabilities at any severity. Tests: no hidden skips — the alarming-looking guards are dormant (83 passing, 0 pending).

Passed along but NOT independently verified

unverified

Plausible, not confirmed by me. Treat as leads:

  • Artifact asset tokens are HMAC(sessionId) with no expiry and no per-path scope, so a leaked URL grants all assets in that session for the process lifetime.
  • artifact-review.js:654,684,694 use plain realpathSync rather than .native, so 8.3 short names survive and legitimate assets may 403 on CI runners.
  • session-store.js:46 test-sandbox guard compares raw strings — a short name or case variant could let a test write the real store.
  • No rate limiting on WS upgrade, file upload/download/write.
  • VS Code tunnel URLs embed tkn=<connectionToken> (confirmed at vscode-tunnel.js:650,667,815); whether they reach logs I did not confirm. Note this is VS Code's own mechanism, not an invention here.
  • EventSource cross-session desync in the file browser on rapid tab switching.

Rejected after checking

Reported by the surveys, refuted against source. Recording these because the false-positive rate matters when weighing the rest:

  • All three "HIGH" client findings. Flow-control wedge — the decrement is the first statement, before anything throwable. Snapshot-cache unbounded growth — pruneOrphans is called (app.js:341), the agent searched the wrong name, and an LRU bounds it anyway. Session-creation lockout — the flag has one read site and routes rather than gating; it cannot lock anyone out.
  • _outputTail not cleared on session switch — it is, at app.js:2759.
  • Crash-file prune regex mismatch — the pattern is /^sessions\.json\.crash(\.\d+)?$/; the suffix group is optional.
  • "Corrupted sessions.json causes permanent loss" — that path does back up. The unrecoverable one is its neighbour (finding 5).
  • Sessions older than 7 days discarded on load — consistent with the documented eviction policy, not a bug.
